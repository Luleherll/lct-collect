# LCT Collect interaction contract

Authoritative business context: README.md (accepted scope/protocol), src/lib/domain.ts (UGX/workday), firestore.rules (permissions and write validation), docs/ACCOUNT_SETUP.md (manual Auth/profile administration), docs/RECOVERY.md and docs/PILOT.md (operations and release gates). User decisions: no Cloud Functions, no offline writes, use Account Name and Unique Number (LCT002) as the account number, hide old account IDs and numbers, preserve existing links through an owner-approved one-time ID bridge, manually create Auth users. This contract records UI consequences; it does not change those policies.

Searches and financial filter text stay in memory: account names/identifiers must not leak to browser history, copied URLs or referrers. History uses bounded session batches; entries load only for a selected day. Header navigation changes routes inside the mounted app, preserves unchanged subscriptions and cannot silently discard a dirty draft. Back/forward navigation updates the screen and reading context.

Auth defaults to browser-session persistence, with in-memory fallback if storage is blocked. Viewed records automatically use persistent Firestore caching, with the SDK memory fallback if persistent storage is unavailable. Login explains caching and sign-out cleanup; no opt-in is required. No financial form payload is stored. A save requires durable session storage of its recovery ID before the server request; blocked storage stops with instructions and never leaves a busy state stuck.

Changing selected member with entered amounts requires an explicit discard decision. Successful financial mutation clears draft and shows a dismissible six-second toast with account and amounts; saved entries remain available in Recent entries. Uncertain mutation retains the same ID, disables further entry and checks the server; it never automatically replays. Viewer checks show an immediate audited Undo action. The field estimate is not a member balance.

Directory transactions reserve account numbers for one ID permanently and compare preview fingerprints. Old data must be backfilled before enabling new writes; the explicit import Apply phase prepares existing reservations before applying changes. No number reassignment across IDs, no deletion of omitted accounts, no activation of inactive accounts. Five-account chunks keep rules document-access limits bounded. Partial failure states the confirmed progress and instructs re-preview; it does not assume a timed-out chunk failed.

Directory identity: new uploads use Account Name and Unique Number, with the exact LCT prefix and zeros. New records use that LCT number as both internal document identity and account number; existing records already carrying an LCT number keep their internal identity. During the approved transition only, Account Id finds an existing legacy document whose account number is still numeric. The old Account Number column is never imported. No name-only matching, deletion or historical snapshot rewriting. Preview and screens expose only name and LCT account number. Missing/ambiguous legacy links block the affected upload instead of guessing.
