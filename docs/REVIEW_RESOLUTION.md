## Compact operator refinement

Collection now uses compact header/search/amount spacing, numeric-only amount edits and a six-second dismissible save toast. Recent entries precedes History in the header; cash breakdown is a dialog opened from Recent entries. Dense recent-entry and directory rows retain full account identifiers, status and details access. The owner chooses CSV from the header and pages through directory matches in batches of 50. Internal navigation retains the mounted app and unchanged record subscriptions; static fallback markup appears before hydration. Offline record viewing caches automatically, without a login checkbox; financial writes remain online-only. Long identities, software keyboards and enlarged text may still require natural document scrolling.

## Members with multiple accounts

The final clarified model supersedes the earlier LCT-as-account interpretation: the original file has 715 member/group identifiers and 820 distinct Ssentezo accounts. Repeated unique identifiers with matching names describe several accounts belonging to the same member. Every distinct real account is retained. The importer skips only identical account rows and flags conflicting member/account identities. Admin and agent search use shared expandable member cards; account counts and explicit account selection expose the relationship. ABC cards have a Group chip. Existing IDs and financial references are preserved; no duplicate-removal or automatic deactivation is part of this change. Rules validate separate member and account identifiers, immutable ownership, verified legacy restoration and optional entry member-number snapshots. The private source file is used for aggregate parser validation only and is not committed.
